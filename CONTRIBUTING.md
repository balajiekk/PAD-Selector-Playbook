# Contributing

Contributions are welcome, especially practical PAD automation patterns that solve repeatable UI automation problems.

## Recipe expectations

A new recipe should explain:

1. The automation problem
2. Why the standard approach is unreliable or insufficient
3. The selected automation strategy
4. The selector/targeting pattern
5. Validation and recovery
6. Known limitations
7. Environment assumptions

## PAD files

Runnable `.pad` files should be added only when the flow has been tested and is safe to share. Avoid committing credentials, connection details, production URLs, customer data, screenshots containing sensitive information, or environment-specific secrets.

## Documentation style

Keep examples:

- Practical
- Clear
- Reproducible
- Focused on maintainability
- Explicit about limitations

Prefer a pattern that teaches the reasoning behind the solution rather than a selector that works only for one screen.
